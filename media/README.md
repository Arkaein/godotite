# Media

The images for the GitHub page and the store listings, and how each is made, so they can be redone
the same way. None of this is in the download (`.gitattributes`) or imported by Godot (`.gdignore`).

## Files

| File | Size | Used by | Made by |
|---|---|---|---|
| `../icon.svg` | 128×128 | the project icon, the source of every icon below | `tools/make_icon.py` |
| `icon.png` | 256×256 | README header, Asset Library icon (square, ≥128 px) | `tools/make_media.sh` |
| `thumbnail.png` | 1280×720 | Asset Store thumbnail (16:9) | `tools/make_media.sh` |
| `screenshot_material.png` | 1280×720 | hero, social preview, store previews | taken in the demo |
| `screenshot_cluster.png` | 1280×720 | hero, social preview, store previews | taken in the demo |
| `screenshot_levels.png` | 1280×720 | hero, social preview, store previews | taken in the demo |
| `hero.png` | 1280×720 | the image at the top of the root README; a fourth Asset Store preview | `tools/make_banners.py` |
| `social_preview.png` | 1280×640 | GitHub's social preview, shown by link previews (LinkedIn and others) | `tools/make_banners.py` |

Every generated file is deterministic: rerunning the tools on the same inputs gives the same
pixels (checked 2026-10-19 against the committed images, with ImageMagick 6.9.12 and Pillow 10.2).

## Redrawing

From the repository root:

```
media/tools/make_media.sh          # icon.png, thumbnail.png, hero.png, social_preview.png
media/tools/make_media.sh --icon   # the same, after redrawing icon.svg from make_icon.py
```

Needs `python3` with Pillow, ImageMagick 6 (`convert`, `identify`) and the DejaVu fonts
(`fonts-dejavu` on Debian and Ubuntu). After new screenshots, run it, then look at `hero.png` and
`social_preview.png`: the labels and title sit where the old screenshots had sky and plain
terrain.

## The design

**Palette.** Backdrop `#1f2a44` (deep blue) in the icon, thumbnail, label boxes and title band.
The icon's levels, coarsest to finest: `#ffd166` (yellow), `#7bd389` (green), `#4ecdc4` (teal),
picked by hand to suggest the level debug view. They are not its colors: that view is a hue ramp
across the DAG's levels (`tools/cluster_debug.gdshader` in the addon).

**Icon** (`make_icon.py`). The LOD idea in one triangle: an equilateral-ish triangle on a rounded
square, cut into a 3×3 lattice of nine triangles, each split in four again when its center is
within 80 px of the bottom-left corner, and again within 46 px. Each piece is filled with its
level's color and stroked in the backdrop color, 1.4 px. Those constants are at the top of the
script.

**Thumbnail.** The icon at 560 px, centered on 1280×720 of backdrop.

**Hero.** The three screenshots in vertical thirds, material, cluster, levels, left to right, with
borders slanted 120 px top to bottom and drawn as 4 px backdrop lines. Labels "Materials",
"Clusters", "LOD levels", DejaVu Sans Bold 26 px in white, on backdrop boxes at 85% opacity,
centered at the bottom of each slice.

**Social preview.** 1280×640: a 210 px backdrop band holding the icon (150 px), "Godotite" (DejaVu
Sans Bold 76 px, white) and the tagline (DejaVu Sans 34 px, `#c8d4eb`); below it, rows 110 to 540 of
the hero's slices, without labels, so the skyline shows. The tagline is `TAGLINE` in
`make_banners.py`; keep it the same as the README's subtitle and the GitHub description.

## Taking the screenshots

All three from **one camera**, so the hero's slices line up.

1. In this repository, generate the demo terrain at its default settings (**DemoTerrain ›
   Generate**) and run the demo. The window is 1280×720 (Project Settings › Display › Window).
2. Fly to the view, or keep the start camera. Hide the overlay with **H**. Leave the error threshold
   at its default, 2 px.
3. **Tab** cycles the cluster view, a checker and the terrain's own colors; **C** changes what the
   cluster view colors: cluster, level, error. Take:
   - `screenshot_material.png`: the terrain's own colors;
   - `screenshot_cluster.png`: the cluster view, colored by cluster;
   - `screenshot_levels.png`: the cluster view, colored by level.
4. Save them as PNG at 1280×720, without window borders, and run `media/tools/make_media.sh`.

## The text

The words are written by hand (with Claude), not generated by a script; what can be redone is
where they live and where their facts come from.

- **Root `README.md`**, the GitHub front page, in this order: icon and name, a one-line subtitle,
  badges (Godot version, license, version), the hero, two paragraphs on what it does, Features, How
  it works (diagram and the crack-free argument, linking ALGORITHM.md), Results, Quick start,
  Documentation (a table of the three docs), Requirements and limits, About. The guide
  (`addons/godotite/README.md`) is the full manual and is the same file store users get; the root
  README only introduces and links.
- **Facts in it, and their sources:**
  - line counts: `cat addons/godotite/native/*.cs | wc -l` (C#) and
    `cat addons/godotite/*.gd addons/godotite/tools/*.gd | wc -l` (GDScript, the demo left out);
  - Results: the development project's GODOTITE.md, step 18 (the 13.8M world, 2026-09-26);
  - tested versions: the versions in RELEASING.md's release steps;
  - the version badge: `plugin.cfg`, updated with each release.
- **Store listing text** (name, category, tags, summary, description, AI disclosure) and the GitHub
  About box (description, topics): `RELEASING.md`, filled in as written there. The Asset Library
  description is plain text: no Markdown.
